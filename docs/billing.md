# 用量与计费

这里是桥接服务的本地预算账本，不是阿里云官方账单，也不是支付系统。费率由管理员按 Agent 配置，项目不自动推断模型价格。

## 计算口径

每次已提交任务结束后：获取最新 Session 累计统计，减去系统保存的上次累计值。首次启用计费先记录基线，不补扣历史消耗。

| 项目 | 用量 | 单价单位 |
| --- | --- | --- |
| 隐式缓存模式的普通输入 | 总输入增量 − 缓存读取增量 | 元 / 百万 Token |
| 显式缓存模式的普通输入 | 总输入增量 − 缓存读取增量 − 缓存创建增量 | 元 / 百万 Token |
| 缓存读取 | cache_read_input_tokens 增量 | 元 / 百万 Token |
| 显式缓存创建 | cache_creation_input_tokens 增量 | 元 / 百万 Token，必须独立填写 |
| 输出 | output_tokens 增量 | 元 / 百万 Token |
| 活跃时间 | active_seconds 增量 ÷ 3600 | 元 / 小时，默认 0.5 |
| web_search | 本轮完整 tool_call，按 call_id 去重 | 元 / 次，默认 0.03 |

隐式缓存创建缺失/null 按 0 处理，不单独收费。显式模式缺字段、累计值回退或普通输入计算为负数时保留待结算，不能静默按 0 收费。模式与费率在任务提交时锁定，后续修改不影响该轮和历史账单。

例如显式缓存总输入 44,969、读取 26,373、创建 18,578，则普通输入为 **18 Token**。读取和创建分别按各自单价计算。

费用以整数微元保存（1 元 = 1,000,000 微元）；每个分项使用 Decimal 四舍五入到微元后求和。不会按整小时向上取整。web_search 按完整调用计次，不按返回条数；本地规则不会因工具失败自动免单。

## 预算和异常

- 设置的是累计总额度，提高总额可补充余额；修改总额不会清零已扣费用。
- 已配置 Agent 单价时，剩余 = 总额 − 已扣；小于等于 0 拒绝新执行，`/usage` 仍可用。
- 单轮可超出剩余额度，因此余额可能为负；没有进行预授权或费用预估。
- Agent 未配置单价时，不做本地扣费，也不按预算拦截消息、定时任务或新会话，即使 Bot 预算为 0 或已用尽也可执行。配置单价后启用计费及预算限制；不补扣首次启用前的历史消耗。已开始计费的任务仍按其锁定费率结算。百炼云端收费不受此开关影响。
- 定时任务独立 Session 的费用仍扣所属 Bot，不混用聊天 Session 的 checkpoint。
- 用量查询/工具事件补查失败时等待结算恢复，不能让漏掉的用量成为免费消耗。
- 本地账本、Bot 扣减、Session checkpoint 与任务结算状态在同一 SQLite 事务内提交。

管理后台的 Session 用量是当前会话的累计值，手动刷新；自助 API 中 settled_usage 是已结算总量，current_session 是当前会话累计值，两者存在重叠，不可相加。
